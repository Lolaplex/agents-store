# T14 — correspondence matching (`Match`)

## Goal

Propose `correspondence` rows between two attr namespaces (MEGAPLAN §6.1:
"propose correspondences (structural/name match)"). Proposals are
heuristic and untrusted — `status='proposed'` until witnessed. The human
(or test) confirms; a witness certificate then raises the status. This is
the model-management `Match` operator, kept decidable: candidates are
generated by structural rules, not guessed semantics.

## API (`src/agents_store/match.py`)

- `propose(conn, left_ns: str, right_ns: str) -> list[int]` — for each
  pair `(a_from in left_ns, a_to in right_ns)`:
  - same local name AND same `value_type` AND same `cardinality`
    → `kind='equal'`, status `proposed`
    (e.g. `jcal:summary`/`md:summary` pairs; jcal vs core needs an
    explicit alias table — see below)
  - local name of `a_from` is a strict prefix/substring of `a_to`'s (or
    reverse), same `value_type` → `kind='refines'`
  - otherwise no row. Idempotent: re-running proposes no duplicates
    (same `a_from,a_to,kind` → skip).
- `ALIAS` table (module constant, declared in code, not magic):
  `{jcal:summary → title, jcal:dtstart → when, jcal:dtend → end,
    jcal:status → status}` — names the *claimed* alignments a human
    confirms; `propose` consults it for cross-vocabulary equal edges.
  Rationale: name-equality alone can't align `dtstart`↔`when`; the alias
  table is the explicit, auditable seed of candidate semantics.
- `witness(conn, corr_ids: list[int], corpus_e: list[str]) -> cert_id` —
  witness check: for each `equal` edge, sample entities carrying `a_from`
  and verify the mediated value round-trips (value survives
  encode→decode through both attr specs). Pass → `certificate`
  (subject=`corr:<id>`, tier=`witness`, result=`pass`) and
  `correspondence.status='witnessed'`. Fail → `result='fail'`, status
  stays `proposed`.
- `confirm`/`reject` helpers set human intent before witnessing:
  unconfirmed proposals are not witnessed (acceptance wants "confirm 2
  correspondences").

## Rules

- Correspondences are per-namespace-pair; both directions are derived by
  `derive.py` — never store two rows for one edge.
- `lens_ref` stays NULL in POC (no lens code yet).
- `proven` status is not reachable in this card (Lean tier is §6.8).

## Tests

- `propose` on `jcal`↔core yields exactly the alias-table `equal` edges
  + no refines noise on this vocabulary.
- re-run is idempotent (no duplicate rows).
- `witness` on valid corpus → `witnessed` + pass certificate;
  tampered corpus (type-incompatible value) → fail cert, stays proposed.
- unconfirmed edge cannot be witnessed (witness skips unconfirmed).
